# GitHub Copilot トークンとAIクレジットの仕組み・賢い使い方

> 参考:
> - [Usage-based billing for individuals - GitHub公式ドキュメント](https://docs.github.com/en/copilot/concepts/billing/usage-based-billing-for-individuals)
> - [Best practices for using GitHub Copilot - GitHub公式ドキュメント](https://docs.github.com/en/copilot/using-github-copilot/best-practices-for-using-github-copilot)

---

## トークンとは

AIが文章を処理するときの**最小単位**のこと。

- 日本語の場合、だいたい **1〜2文字 = 1トークン** が目安
- 英語の場合、だいたい **1単語 = 1〜2トークン** が目安
- コードも同様にトークン単位で処理される

### トークンの種類

| 種類                   | 意味                                            |
| ---------------------- | ----------------------------------------------- |
| **入力トークン**       | 自分がCopilotに送った内容（質問・コード・文脈） |
| **出力トークン**       | Copilotが返してきた内容（回答・生成コード）     |
| **キャッシュトークン** | モデルが再利用・保持しているコンテキスト        |

### コンテキストウィンドウとは

AIが「一度に読める範囲」のこと。この範囲に収まらない情報はAIには見えない。

例えるなら、**机の上に広げられる書類の量**に限りがある状態。
会話が長くなるほど、古いやりとりがコンテキストウィンドウから押し出されていく。

## AIクレジットとは

2026年6月からの新しい課金単位（旧：プレミアムリクエスト）。

```
1 AI credit = $0.01 USD
```

Copilotを使うと「入力トークン + 出力トークン + キャッシュトークン」の合計量に応じてAIクレジットが消費される。

**消費量に影響する2つの要素**:
1. **モデルの種類** — 高性能なモデルほど1トークンあたりのコストが高い
2. **トークン数** — やりとりが長くなるほど消費が増える

---

## 消費量の多い・少ないパターン

### 消費が少ない（AIクレジットを使わない）

- コード補完（インライン補完）
- Next Edit Suggestions

> 有料プランではこれらは**無制限**。気にせず使ってよい。

### 消費が少ない（1回あたりの消費が小さい）

- 軽量モデル（例: Claude Haiku、GPT-5 mini）を使った短いチャット
- 「このコードを説明して」などの1問1答

### 消費が多い

- 高性能モデル（例: Claude Sonnet、Opus）を使った長い会話
- Agent mode で複数ファイルにまたがる作業
- Copilot cloud agent での自律的なタスク実行

---

## AIクレジットを節約するための実践的なヒント

### 1. 用途に合ったモデルを選ぶ

公式ドキュメントより:
> *「軽量なモデルに切り替えることは、使用量の上限を延ばす方法の1つ」*

| 目的                         | 推奨モデル                              |
| ---------------------------- | --------------------------------------- |
| 簡単な質問・コード補完       | GPT-5 mini / Claude Haiku（軽量・安い） |
| 複雑なロジックの設計・相談   | Claude Sonnet / GPT-4.1（バランス）     |
| 難しいアーキテクチャ検討など | Claude Opus（高性能・消費大）           |

### 2. 会話を適切にリセットする

公式ドキュメントより:
> *「特定のリクエストが有益なコンテキストでなくなった場合は、会話から削除する。または会話全体が不要な場合は新しい会話を始める。」*

- 話題が変わったら**新しいチャットを開く**
- 長くなった会話は古いメッセージを削除する
→ コンテキストウィンドウを無駄に埋めず、消費を抑えられる

### 3. 関係ないファイルを閉じる

公式ドキュメントより:
> *「IDEでCopilotを使う場合は、関連ファイルを開き、無関係なファイルは閉じる。」*

Copilotは開いているファイルをコンテキストとして読み込む。
無関係なファイルを開いたままにすると、余分なトークンを消費する。

### 4. 質問を具体的・簡潔にする

公式ドキュメントより:
> *「プロンプトエンジニアリング（=Copilotが理解しやすいようにリクエストを構造化すること）は、有益な回答を生成する上で重要な役割を果たす。」*

**悪い例**: 「このコードをよくして」  
**良い例**: 「このPHP関数のSQLインジェクション対策をしてください。PDOのプリペアドステートメントを使ってください。」

## Agent mode を安く使うための戦略

Agent modeはCopilotの中で**最も消費が大きい機能**。1つのタスクにつき、Copilotが自律的に何度もモデルを呼び出す（ファイル確認・計画・修正・確認…）ため、チャット1回と比べて消費量がまったく異なる。

公式ドキュメントより:
> *「エージェント機能（agent modeやCopilot cloud agent）は、1つのタスク内で複数回モデルを呼び出すことがある。大規模なコードベースで複雑なエージェントセッションを実行すると、チャットの簡単な質問よりはるかに多くの使用量を消費する。」*

### 対策1：Agent modeでも軽量モデルを選ぶ

Agent modeはモデルを自由に選択できる。高性能モデルが必須な場面は少ない。

| タスクの難易度                     | 推奨モデル                | 理由                                 |
| ---------------------------------- | ------------------------- | ------------------------------------ |
| ファイル整理・リネーム・簡単な修正 | GPT-5 mini / Claude Haiku | 何度も呼ばれるので安いモデルが効果大 |
| ロジックの実装・バグ修正           | Claude Sonnet / GPT-4.1   | バランスよく使える                   |
| 複雑なアーキテクチャ変更           | Claude Opus               | 本当に必要なときだけ                 |

### 対策2：タスクのスコープを小さく絞る

Agentはタスクが曖昧・広いほどループ回数が増え消費が膨らむ。

**消費が多いパターン（避ける）**:
```
「このプロジェクト全体をリファクタリングして」
```

**消費を抑えるパターン（推奨）**:
```
「UserController.php の createUser() メソッドだけをバリデーション付きに書き直して」
```

### 対策3：使う前に関係ないファイルを閉じる

Agentはエディタで開いているファイルもコンテキストとして読み込む。
不要なファイルを閉じておくだけで、毎回のモデル呼び出しのトークン量が減る。

### 対策4：Agentが不要な作業はインラインチャットで済ませる

Agent modeを使うべき場面とそうでない場面を意識するだけで節約になる。

| 作業内容                   | 推奨する機能                             | 理由                             |
| -------------------------- | ---------------------------------------- | -------------------------------- |
| 1つの関数を書いてほしい    | **インライン補完 or インラインチャット** | AIクレジット消費が少ない or ゼロ |
| コードを説明してほしい     | **Copilot Chat**                         | 1回のやりとりで済む              |
| 複数ファイルにまたがる修正 | **Agent mode**                           | このときだけ使う価値がある       |
| テストを全部書いてほしい   | **Agent mode（スコープ限定）**           | ファイルを1つに絞って指示する    |

## 使いこなしの優先順位まとめ

1. **コード補完は無制限なので積極的に使う** — AIクレジット不要
2. **チャットは新しい話題のたびに会話をリセットする** — 無駄なトークン消費を防ぐ
3. **軽い作業には軽いモデルを選ぶ** — AIクレジットの消費を抑える
4. **Agent modeは消費が大きいと心得る** — 複雑なタスクのときだけ使う
5. **カスタム指示（`.github/copilot-instructions.md`）を設定する** — 毎回説明するコストを省ける
