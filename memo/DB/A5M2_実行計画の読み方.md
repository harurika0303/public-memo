## 概要

A5M2(A5:SQL Mk-2)は、SQLの実行計画(アクセスプラン)を取得・表示する機能を備えたWindows用GUI SQLクライアントです。<cite index="7-1">実行計画取得機能はRDBMSがSQLを実行する際の実行計画(アクセスプラン)を表示するもので、Oracle Database、IBM DB2、SQL Server、MySQL、PostgreSQLに対応しています。</cite>

実行計画を確認することで、SQLがデータベース内部でどのように処理されているかを把握し、パフォーマンス改善のヒントを得ることができます。

---

## 実行計画の表示方法

### 基本操作
<cite index="2-1">A5:SQL Mk-2では、SQLエディタで実行計画を見たいSQLの上にキャレット(カーソル)がある状態で、メニューから[SQL(S)]→[SQLの実行計画(J)]を選択するか、ショートカットキー Ctrl+E で表示できます。</cite>

> 💡 **補足**: 環境設定によっては、`Ctrl+E` が通常のSQL実行に割り当てられ、実行計画の表示は `Shift+Ctrl+E` になっている場合があります。<cite index="5-1">「Ctrl+EでSQLを実行する」を設定している場合、SQL実行計画は Shift+Ctrl+E で行うようになります。</cite>自分の環境でどちらが割り当てられているかは、メニューの[SQL(S)]から確認してください。

### 表示形式
<cite index="2-1">実行計画の表示の仕方はデータベース製品ごとに異なりますが、多くのデータベース製品ではツリー状の情報として表現されるため、A5:SQL Mk-2でもツリービューで実行計画を表示します。</cite>

<cite index="2-1">ツリーの葉(端)の部分から処理が行われ、根(ルート)に向かって絞り込み・結合・集計・ソートといった処理が順番に行われていきます。</cite>つまり、**下(または末端)から上(または起点)に向かって読む**のが基本です。

## SQL Serverで実行計画を使う際の事前準備

SQL Serverで実行計画を取得するには、対象ユーザーに `SHOWPLAN` 権限が付与されている必要があります。権限がない場合、実行計画の取得時にエラーとなります。

<cite index="8-1">SHOWPLANの権限を付与することで実行計画が取得できるようになります。SQL Server Management Studio (SSMS) から下記のSQLを実行して権限を付与します。</cite>

```sql
GRANT SHOWPLAN TO [ユーザー名] WITH GRANT OPTION;
```

> ⚠️ **注意**: `[ユーザー名]` の部分には対象のデータベースユーザー名を指定します。権限付与にはデータベースの管理者権限が必要です。

他のデータベース製品でも同様に事前準備が必要な場合があります。
- **Oracle Database**: `PLAN_TABLE` 表を先に作成しておく必要があります
- **IBM DB2 UDB**: `EXPLAIN` 表を先に作成しておく必要があります

<cite index="3-1">これらは[SQL(S)]-[SQLの実行計画(T)...]を選択するか、Ctrl+Eを押下することで取得できます。出力される内容は各データベース製品ごとに異なります。</cite>

## 実行計画の基本的な読み方

### 1. 読む方向を意識する

実行計画はツリー構造で表示され、**末端(リーフ)のノードから処理が開始**され、**上位(ルート)に向かって**結合・絞り込み・集計・並べ替えが行われていきます。したがって、実際の処理順序を追うには、ツリーの深い階層(下側・内側)から見ていく必要があります。

### 2. 各ノードで確認する情報

ノードごとに以下のような情報が表示されます(データベース製品によって表記は異なります)。

| 項目 | 内容 |
|---|---|
| 処理内容(オペレーション) | テーブルスキャン、インデックスシーク、結合方式など |
| コスト(Cost) | そのステップの処理コストの見積もり |
| 推定行数(Rows) | そのステップで処理される見込みの行数 |
| 実測時間(Actual Time) | 実際にかかった処理時間(ANALYZE系実行時) |
| 実測行数(Actual Rows) | 実際に処理された行数 |

### 3. PostgreSQLでの表示例(参考)

PostgreSQLの `EXPLAIN ANALYZE` を実行した場合の出力例です。

```
Sort (cost=858.39..883.39 rows=10000 width=42) (actual time=10.102..11.431 rows=10000 loops=1)
  Sort Key: stock DESC
  Sort Method: quicksort  Memory: 1088kB
  -> Seq Scan on bookstock (cost=0.00..194.00 rows=10000 width=42) (actual time=0.060..2.295 rows=10000 loops=1)
Planning Time: 0.272 ms
Execution Time: 12.888 ms
```

主な項目の意味:
- **actual time**: <cite index="1-1">並べ替え操作に実際にかかった時間をミリ秒単位で示しています。</cite>
- **Planning Time**: <cite index="1-1">クエリを実行する計画(実行計画の生成)にかかった時間です。</cite>
- **Execution Time**: <cite index="1-1">実際のクエリ実行全体にかかった時間です。</cite>

このように、`cost` は見積もりコスト、`actual time` は実測時間を示しており、両者に大きな差がある場合は統計情報が古い可能性があるなど、チューニングの手がかりになります。

## 注目すべきポイント

### 全件スキャン(フルスキャン)を見つける

<cite index="2-1">実行計画で最初に確認すべきは、無駄なテーブルの全件読み込みが発生していないかという点です。</cite>テーブル全体読み込みは、データベース製品によって以下のように表現が異なります。

| データベース製品 | フルスキャンの表記 |
|---|---|
| Oracle | `TABLE ACCESS FULL` |
| PostgreSQL | `Seq Scan` |
| MySQL | `ALL` |
| SQL Server | `Table Scan` / `Clustered Index Scan` |

<cite index="2-1">A5:SQL Mk-2では、これらのフルスキャン処理は赤字で表示されます。</cite>色分けによって問題箇所を視覚的にすぐ見つけられるのがA5M2の特徴です。

同様に、<cite index="3-1">パフォーマンス上問題のある可能性のある個所は赤い色で表示され、この結果を見てSQLのパフォーマンスチューニングを行うことができます。</cite>

### 統計情報の鮮度を疑う

<cite index="2-1">できるだけ高速な読み込み方法・結合方法を採用するために、各データベース製品は統計情報(データの件数や種類・偏りなど)をバックグラウンドで収集し、判断基準としています。多くの場合は自動で採取されます。</cite>

ただし、<cite index="2-1">大量データを投入した直後などは統計情報が実データと合っておらず、遅い実行計画になってしまうことがあります。この場合、手動で統計情報を取得するコマンドを活用することで、速い実行計画に改善できることがあります。</cite>

## データベース製品ごとの表示の違い

<cite index="3-1">出力される内容は各データベース製品ごとに異なり、SQL実行計画をサポートするデータベース製品はOracle Database、IBM DB2 UDB(いずれも事前にテーブル作成が必要)など複数あります。</cite>SQL Serverの場合は前述の `SHOWPLAN` 権限付与のみで利用可能です。

読み方の基本(末端から根に向かって読む、コストと推定/実測行数を確認する、赤字箇所に注目する)は共通していますが、演算子(オペレーター)の名称や表示される統計情報の粒度は製品ごとに異なるため、対象データベースのオペレーター名称(結合方式やスキャン方式の名称など)を別途把握しておくと読み解きがスムーズになります。

## パフォーマンスチューニングの進め方

実行計画を確認した後の一般的な改善アプローチです。

1. **赤字(問題箇所)のノードを特定する** — フルスキャンなどコストの高い処理を探す
2. **推定行数と実測行数の乖離を確認する** — 乖離が大きい場合は統計情報の更新を検討
3. **インデックスの要否を検討する** — 検索条件・結合条件に対して適切なインデックスがあるか確認
4. **SQLの書き方を見直す** — 不要なサブクエリ、暗黙の型変換、SELECT * などを見直す
5. **改修後、再度実行計画を取得して比較する** — 改善前後でコスト・処理内容がどう変化したか確認

<cite index="2-1">遅いSQLがある場合は、この実行計画を見ながら、どのようにSQLを修正するか・インデックスを追加するかを考えていくことになります。</cite>

## トラブルシューティング

### 実行計画が取得できない・エラーになる(SQL Server)
- 対象ユーザーに `SHOWPLAN` 権限が付与されているか確認する
- SSMSなど別ツールから `GRANT SHOWPLAN TO [ユーザー名]` を実行する

### 実行計画が取得できない(Oracle)
- `PLAN_TABLE` が作成されているか確認する(未作成の場合は作成が必要)

### 実行計画が取得できない(DB2)
- `EXPLAIN` 表が作成されているか確認する

### PostgreSQLで実測時間(ANALYZE情報)が表示されない
バージョンによっては `EXPLAIN ANALYZE` を実行しても実測時間が表示されないケースが報告されています。この場合、<cite index="6-1">Explain文を実行せずとも、該当SQLで Ctrl+E を押下すると実行計画が表示される場合があります(ただしANALYZEオプションなしの見積もりベースの表示になります)。</cite>

## まとめ

- A5M2の実行計画表示は `Ctrl+E`(環境によっては `Shift+Ctrl+E`)で呼び出す
- ツリー表示は**末端から根に向かって**読む
- **赤字表示**の箇所(フルスキャンなど)を最優先でチェックする
- SQL Serverでは事前に `SHOWPLAN` 権限の付与が必要
- 推定値と実測値のズレが大きい場合は統計情報の更新を検討する
