# DB内部構造 総合ガイド

RDB(リレーショナルデータベース)が内部で「どうやってデータを保存し、どうやってSQLを処理しているか」を、**土台となる物理的な仕組みから順番に(ボトムアップに)**学べるようにまとめた資料群です。

対象は PostgreSQL / MySQL(InnoDB) / SQL Server の3製品。それぞれの共通する考え方と、製品ごとの実装の違いの両方に触れます。

---

## この資料群の読み方

- SQLを書けるようになった次のステップとして、「なぜこのSQLは遅いのか」「なぜロック待ちが起きるのか」を自分で推測できるようになることを目標にしています。
- 各ファイルは独立して読めますが、**上から順番(01→07)に読むと、下の層(ディスク上の物理構造)から上の層(SQLの実行)へと知識が積み上がる**ように設計しています。
- 難しく感じたら、まず「たとえ話」の部分だけ読んで全体像をつかみ、SQLや専門用語は読み飛ばしてOKです。
- 記載内容の根拠(出典)は、各セクションの説明文中に直接リンクを埋め込んでいます。加えて各ファイル末尾に「参考文献」として一覧化しているので、あとから元情報にすぐアクセスできます。

## 全体像を先取りする1枚図

SQLが実行されるとき、内部ではおおよそ以下の層を上から下へ、そして下から上へと処理が流れます。この資料もこの構造に沿って**下(物理層)から上(SQL層)**へと解説していきます。

```
┌─────────────────────────────────────────┐
│  クライアント (アプリケーション / SQLクライアント) │
└───────────────────┬─────────────────────┘
                    │ SQL文
┌───────────────────▼─────────────────────┐
│  ① パーサ(構文解析)                        │  … 07章
│  ② オプティマイザ(実行計画の決定)             │  … 07章
│  ③ エグゼキュータ(実行計画の実行)             │  … 07章
├───────────────────────────────────────────┤
│  ④ トランザクション管理・同時実行制御(MVCC/ロック)│  … 05章
│  ⑤ ログ管理(WAL/トランザクションログ)          │  … 06章
├───────────────────────────────────────────┤
│  ⑥ インデックス(B-Treeなど)                  │  … 03章
│  ⑦ バッファプール(メモリキャッシュ)            │  … 04章
├───────────────────────────────────────────┤
│  ⑧ ストレージ(ページ・ファイル)                │  … 02章
└───────────────────┬───────────────────────┘
                    ▼
                  ディスク(SSD/HDD)
```

- **本資料の解説順は ⑧→⑦→⑥→⑤→④→①〜③** に近い、つまり「データが実際に置かれている場所」から先に理解し、そのあとで「複数人が安全に触るための仕組み」「SQLがどう解釈されるか」へ進みます。これが「ボトムアップ」の意味です。

## 用語の前提知識

- **RDBMS**: Relational Database Management System。行と列の表(テーブル)でデータを管理するDB製品群。PostgreSQL・MySQL・SQL Server・Oracleなど。
- **ストレージエンジン**: テーブルのデータを実際にディスクへ読み書きする部品。MySQLは複数のストレージエンジンを差し替え可能な設計になっており、標準は InnoDB です。PostgreSQL・SQL Server は基本的に単一のストレージエンジンを内蔵しています。
- 本資料でMySQLと言う場合は、特に断りがない限り標準ストレージエンジンである **InnoDB** を前提とします。
