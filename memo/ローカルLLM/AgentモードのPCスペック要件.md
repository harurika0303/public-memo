# AgentモードでのローカルLLM PCスペック要件

高品質なアプリ（セキュア・保守しやすい）を自律的に生成するために必要なスペックのまとめ。

---

## なぜスペックが重要か

Agentモード（Cline等）では以下が同時に求められるため、モデル品質が直結する。

- Clineのシステムプロンプトが非常に長い（2000〜4000トークン）
- 複数ファイルを横断した設計の一貫性維持
- セキュリティ要件（SQLインジェクション・XSS・認証設計など）の自律的な適用
- マルチステップのツール呼び出し（ファイル作成→テスト→修正のループ）

---

## モデルサイズと品質の現実

| モデルサイズ | Agentとしての実用性                                  | 代表モデル        |
| ------------ | ---------------------------------------------------- | ----------------- |
| 7B〜8B       | ❌ 指示逸脱・セキュリティ考慮なし                     | Llama 3.1 8B      |
| 14B〜20B     | △ 単純なCRUDは動く。複雑な要件は迷子になりやすい     | gpt-oss:20B       |
| 32B          | ✅ 実用レベル。セキュア設計・アーキテクチャ維持が安定 | Qwen2.5-Coder-32B |
| 70B          | ◎ GPT-4クラスに近い。複雑な要件定義からの実装も可能  | Llama 3.3 70B     |

> **高品質の自律開発には32B以上が実質的な下限**

---

## 推奨PCスペック（3段階）

### 最低ライン：32B Q4を動かす

| パーツ     | スペック              |
| ---------- | --------------------- |
| GPU        | RTX 4090（VRAM 24GB） |
| RAM        | 32GB以上              |
| CPU        | Ryzen 7 / Core i7以上 |
| ストレージ | NVMe SSD 1TB以上      |

- 対応モデル：`Qwen2.5-Coder-32B Q4`・`DeepSeek-R1 32B`
- 処理速度：約15〜25 tok/s（Agentループに耐える速度）

### 推奨ライン：32B Q6〜70B Q4を動かす

| パーツ | スペック              |
| ------ | --------------------- |
| GPU    | RTX 5090（VRAM 32GB） |
| RAM    | 64GB以上              |
| CPU    | Ryzen 9 / Core i9以上 |

- 対応モデル：`Qwen2.5-Coder-32B Q8`・`Llama 3.3 70B Q2`
- Clineの長いコンテキストにも余裕あり

### ハイエンド：70B フル品質

| パーツ | スペック                                                |
| ------ | ------------------------------------------------------- |
| GPU    | RTX 4090 × 2台（VRAM 48GB） または RTX 6000 Ada（48GB） |
| RAM    | 128GB以上                                               |

- 対応モデル：`Llama 3.3 70B Q4`・`DeepSeek-R1 70B Q4`
- コスト面でCloud API（Claude / GPT-4o）と要比較

---

## CPU推論（GPUなし）は非現実的

Clineのようなエージェントループは1タスクで10〜30回のLLM呼び出しが発生する。  
CPU推論だと32B Q4で **1〜5 tok/s** 程度になり、1タスクの完了に30〜60分かかるため実用外。

---

## まとめ

| 目的                                         | 最低GPU                                 |
| -------------------------------------------- | --------------------------------------- |
| 動くだけでいい（品質は低くても可）           | RTX 4070 Ti（12GB）で14B                |
| セキュア・保守しやすい高品質アプリを自律生成 | **RTX 4090（24GB）でQwen2.5-Coder-32B** |
| GPT-4レベルの自律開発                        | RTX 5090 または RTX 4090×2              |

**コスパ最優先の現実解：RTX 4090 + Qwen2.5-Coder-32B Q4**

予算が厳しい場合は、ローカルLLMを補完用に留めてClaude API（月$20程度）をメインにするほうがコスト効率が高いケースも多い。

## GPU 2枚挿し構成（既存PCへの増設）

### 構成例：i7-14700F + RTX 4070（12GB）に1枚追加する場合

| 項目             | 評価                  | 詳細                                                                                 |
| ---------------- | --------------------- | ------------------------------------------------------------------------------------ |
| CPU（i7-14700F） | ✅ 問題なし            | LLM推論中はGPUがメインでCPU負荷は低い                                                |
| PCIeレーン       | ✅ 概ね問題なし        | NVLinkなし（4070は非対応）でPCIe通信になるが推論用途では許容範囲（5〜15%の速度低下） |
| 電源（850W）     | ✅ LLM推論なら問題なし | 推論中はCPUがほぼアイドル → GPU 400W + CPU 50W + その他 100W = 約550W                |
| 廃熱             | ⚠️ 要注意              | 2枚合計400W超。スロットを1つ空けて挿す・ケースエアフロー確認が必要                   |

### 異なるGPUを組み合わせてもよいか

**NVIDIA同士であれば異なるモデルでもOK**（llama.cppのtensor splitが対応）

| 条件                     | 可否                               |
| ------------------------ | ---------------------------------- |
| NVIDIA + AMD 混在        | ❌ バックエンドが異なるため不可     |
| NVIDIA同士・異なるモデル | ✅ 動作する                         |
| VRAMサイズが違う         | ✅ VRAMの比率でレイヤーが分散される |
| 速度が違う               | ⚠️ 遅い方がボトルネックになる       |

### RTX 4070（12GB）と組み合わせた場合の比較

| 追加GPU              | 合計VRAM | 費用感            | 評価                         |
| -------------------- | -------- | ----------------- | ---------------------------- |
| RTX 4070（同モデル） | 24GB     | 約7〜9万          | ◎ バランス最良               |
| RTX 4070 Ti（12GB）  | 24GB     | 約9〜12万         | ◎ 速度も上がる               |
| RTX 4060 Ti（16GB）  | 28GB     | 約5〜7万          | ○ VRAMは増えるが4070より遅い |
| RTX 3080（10GB）     | 22GB     | 約3〜5万（中古）  | △ 32B Q4はVRAMがギリギリ     |
| RTX 3090（24GB）     | 36GB     | 約8〜12万（中古） | ◎ 70B Q2も視野に入る         |

> **コスパ重視なら中古RTX 3090（24GB）との組み合わせが狙い目**。合計36GBでQwen2.5-Coder-32B Q6やLlama 3.3 70B Q2も動く。

### 2枚挿しで面倒になること

**Ollama + Cline の組み合わせなら設定はほぼ不要**。

| ツール        | 手間       | 詳細                                                    |
| ------------- | ---------- | ------------------------------------------------------- |
| Ollama        | ✅ ほぼ自動 | 複数NVIDIAを自動検出・自動分散。特別な設定不要          |
| llama.cpp直接 | ⚠️ 要設定   | `--tensor-split 1,1` のように比率を手動指定する必要あり |
| Cline         | ✅ 不要     | Ollamaに接続するだけなので関係なし                      |

実際に面倒になりやすいこと：

- **非対称構成（VRAMサイズ違い）のチューニング**：4070（12GB）+ 3090（24GB）のような構成では自動分散がうまくいかない場合がある。llama.cppでは `--tensor-split 1,2` のように手動で比率調整が必要になることも
- **モニター出力の競合（稀）**：Windowsがどちらのカードをディスプレイ用に使うか混乱することがある。BIOSでメインGPUを固定しておくと回避できる
- **物理的な冷却**：2枚が隣接すると上側のカードが下側の排熱を吸い込んで温度が上がる。スロットを1つ空けるかケースファンを追加する
- **電源コネクタ**：カード1枚ごとに8pin（または16pin）が必要。ケーブルの取り回しが増える

同モデル2枚構成（4070 × 2）であれば、ソフトウェア面の手間はほぼなく、物理的な取り付けと冷却の確認だけが実作業になる。
