# ADR-0001: 同一仕様を3言語で実装するポートフォリオ戦略

## ステータス
承認済み

## 背景

バックエンドエンジニア（経験 2.5 年・現年収 330 万）として、2〜3 年以内に年収 500 万円を達成するためのポートフォリオ戦略を検討した。

業務経験は Java・PHP のレガシー環境が中心で、モダンなフレームワーク・設計・AWS の実証が転職市場での最大ギャップとして特定された。

ポートフォリオに何を作るかという問いに対し、「アイデアの独自性より技術の正しさ」という評価基準を前提に、題材と言語の組み合わせを検討した。

## 決定

タスク管理 API（シンプルなビジネスロジック）を、以下の3言語・フレームワークで同一仕様のまま順番に実装する：

1. **Spring Boot（Java）** — 業務経験が最も豊富なため1番手
2. **Laravel（PHP）** — 業務経験あり。日本の求人数が多い
3. **NestJS（TypeScript）** — 最も学習コストが高いため3番手

各実装に共通して含める技術要素：
- レイヤードアーキテクチャ（Controller / Service / Repository）
- JWT 認証・認可
- RDS（MySQL または PostgreSQL）
- AWS デプロイ（EC2 or ECS）
- GitHub Actions による CI/CD
- OpenAPI / Swagger によるドキュメント化
- ユニットテスト

## 代替案

**案 A：1言語を深掘りする（採用せず）**

Spring Boot だけを極める方向。設計力・テスト・パフォーマンスチューニングまで深く追求する。

- メリット：1言語の専門家として訴求力が高い。完成が速い
- 不採用の理由：現時点では「1言語の専門家」として転職市場で差別化できるほどの深さに達していない。2〜3 年のタイムラインがあるため幅を出す余地がある

**案 B：新言語（Go・Rust）に切り替える（採用せず）**

市場単価が高い Go を学習してポートフォリオを作る。

- メリット：高単価求人への直接的なアクセス
- 不採用の理由：ゼロからの習得コストが高く、週 10 時間・2〜3 年の制約ではポートフォリオ完成が遅すぎる。既存の Java・PHP 知識を活かせない

**案 C：フルスタック（フロント込み）で作る（採用せず）**

React + バックエンド API の構成でフルスタックとして訴求する。

- 不採用の理由：バックエンド特化という軸をぶらすと訴求先が曖昧になる。フロントの追加は500万達成後のフェーズ2以降に回す

## 結果

- 1本目（Spring Boot）完成後に転職活動を開始し、市場の反応をフィードバックとして2本目の優先度を調整する
- 「なぜ同じものを3回作るのか」という質問に対しては「言語横断的な設計力と、フレームワーク依存ではない実装判断力を示すため」と説明できる
- 3本すべて揃う前に 500 万に到達した場合、3本目は不要になる可能性がある
