# 自動生成とコーディングの境界線

> 具体例: 「投稿（Post）のCRUD機能を作る」シナリオ

---

## 全体の流れ

```
① Artisan コマンドでひな形を生成（自動）
        ↓
② 各ファイルに処理を書く（手動）
        ↓
③ ルートに登録する（手動）
```

Artisan が生成するのは**空のクラスと決まり切った構造だけ**です。実際のビジネスロジック・バリデーションルール・SQL（Eloquent）・画面は自分で書きます。

---

## Step 1: コマンドでひな形を一括生成

```bash
php artisan make:model Post -mrc
```

このコマンド1つで以下の4ファイルが生成されます。

| 生成されるファイル                                | 役割                              |
| ------------------------------------------------- | --------------------------------- |
| `app/Models/Post.php`                             | Eloquent モデル                   |
| `database/migrations/xxxx_create_posts_table.php` | DB テーブル定義                   |
| `app/Http/Controllers/PostController.php`         | コントローラ（CRUD メソッド付き） |
| `database/factories/PostFactory.php`              | テスト用ダミーデータ生成          |

---

## Step 2: 各ファイルの「生成直後」と「手動で書く内容」

### マイグレーション

**生成直後（自動）**
```php
public function up(): void
{
    Schema::create('posts', function (Blueprint $table) {
        $table->id();
        $table->timestamps();
        // ← カラムは id と timestamps しかない
    });
}
```

**手動で書く: テーブルに必要なカラムを追加する**
```php
public function up(): void
{
    Schema::create('posts', function (Blueprint $table) {
        $table->id();
        $table->string('title');              // ← 追加
        $table->text('body')->nullable();     // ← 追加
        $table->foreignId('user_id')          // ← 追加
              ->constrained()
              ->cascadeOnDelete();
        $table->timestamps();
    });
}
```

書いたらマイグレーションを実行してDBに反映します。

```bash
php artisan migrate
```

---

### モデル

**生成直後（自動）**
```php
class Post extends Model
{
    use HasFactory;
    // ← 中身は空
}
```

**手動で書く: 代入可能カラムの指定・リレーションなど**
```php
class Post extends Model
{
    use HasFactory;

    // 一括代入を許可するカラム（セキュリティのため必須）
    protected $fillable = ['title', 'body', 'user_id'];

    // リレーション: Post は User に属する
    public function user(): BelongsTo
    {
        return $this->belongsTo(User::class);
    }
}
```

---

### コントローラ

**生成直後（自動）**
```php
class PostController extends Controller
{
    public function index()   { /* 空 */ }
    public function create()  { /* 空 */ }
    public function store(Request $request) { /* 空 */ }
    public function show(Post $post) { /* 空 */ }
    public function edit(Post $post) { /* 空 */ }
    public function update(Request $request, Post $post) { /* 空 */ }
    public function destroy(Post $post) { /* 空 */ }
}
```

> `--resource` オプションにより CRUD に対応する7つのメソッドが生成されます。ただし中身はすべて空です。

**手動で書く: 各メソッドの処理を実装する**
```php
// 一覧表示
public function index()
{
    $posts = Post::latest()->paginate(10);
    return view('posts.index', compact('posts'));
}

// 新規作成フォーム表示
public function create()
{
    return view('posts.create');
}

// 登録処理
public function store(Request $request)
{
    $validated = $request->validate([
        'title' => 'required|max:255',
        'body'  => 'nullable|string',
    ]);

    Post::create([...$validated, 'user_id' => auth()->id()]);

    return redirect()->route('posts.index');
}

// 詳細表示
public function show(Post $post)
{
    return view('posts.show', compact('post'));
}

// 編集フォーム表示
public function edit(Post $post)
{
    return view('posts.edit', compact('post'));
}

// 更新処理
public function update(Request $request, Post $post)
{
    $validated = $request->validate([
        'title' => 'required|max:255',
        'body'  => 'nullable|string',
    ]);

    $post->update($validated);

    return redirect()->route('posts.show', $post);
}

// 削除処理
public function destroy(Post $post)
{
    $post->delete();
    return redirect()->route('posts.index');
}
```

---

### ルートの登録（すべて手動）

コントローラを生成してもルートは自動登録されません。`routes/web.php` に自分で書きます。

```php
// リソースルート1行で CRUD 用の7ルートを一括登録
Route::resource('posts', PostController::class);
```

`php artisan route:list` で登録されたルートを確認できます。

```
GET    /posts              posts.index   → index()
GET    /posts/create       posts.create  → create()
POST   /posts              posts.store   → store()
GET    /posts/{post}       posts.show    → show()
GET    /posts/{post}/edit  posts.edit    → edit()
PUT    /posts/{post}       posts.update  → update()
DELETE /posts/{post}       posts.destroy → destroy()
```

---

### ビューはすべて手動

Artisan はビュー（Blade テンプレート）を生成しません。`resources/views/posts/` ディレクトリを自分で作り、各ファイルを書きます。

```
resources/views/posts/
├── index.blade.php   ← 一覧画面
├── create.blade.php  ← 新規作成フォーム
├── show.blade.php    ← 詳細画面
└── edit.blade.php    ← 編集フォーム
```

---

## まとめ: 自動 vs 手動

| 内容                                        | 自動生成 | 手動  |
| ------------------------------------------- | :------: | :---: |
| ファイルのひな形・クラス構造                |    ✓     |       |
| マイグレーションの `id()` と `timestamps()` |    ✓     |       |
| コントローラの7つのメソッド名               |    ✓     |       |
| テーブルカラムの定義                        |          |   ✓   |
| モデルの `$fillable`・リレーション          |          |   ✓   |
| コントローラの処理内容                      |          |   ✓   |
| バリデーションルール                        |          |   ✓   |
| ルート登録                                  |          |   ✓   |
| ビュー（Bladeテンプレート）                 |          |   ✓   |

**「型（構造）は自動、中身は手動」** が基本的な考え方です。
