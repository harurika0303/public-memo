# Docker 開発中のホットリロード・ライブリロードについて

> 参考:
> - [Use Compose Watch — Docker Docs](https://docs.docker.com/compose/how-tos/file-watch/)
> - [Bind mounts — Docker Docs](https://docs.docker.com/engine/storage/bind-mounts/)

---

## 「コードを変えるたびに再ビルドが必要？」について

イメージにコードを `COPY` で焼き込む構成（本番向け）では、コード変更のたびに `docker compose build` が必要です。  
しかし**開発中はコードをイメージに焼き込まず、ホストのコードをコンテナに直接見せる**構成を使うのが一般的です。

```
本番構成（コードを焼き込む）:
  ソースコード → COPY → イメージ → コンテナ
  コード変更 → 再ビルド必要

開発構成（コードをマウントする）:
  ソースコード ←→ コンテナ（バインドマウント または Compose Watch で同期）
  コード変更 → 即座に反映 → アプリが自動再起動
```

---

## 方法 1: バインドマウント（シンプル・古くからある方法）

ホストのディレクトリをコンテナ内にそのままマウントします。ホストでファイルを変更すると、コンテナ内にも即座に反映されます。

### compose.yaml の設定

```yaml
services:
  app:
    build: .
    volumes:
      - .:/app                 # ← ホストのカレントディレクトリを /app にマウント
      - /app/node_modules      # ← node_modules はホストのものを使わない（上書きを防ぐ）
    command: npm run dev       # ← nodemon などホットリロード対応コマンドで起動
    ports:
      - "3000:3000"
```

### Dockerfile（開発用）

```dockerfile
# syntax=docker/dockerfile:1
FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
# ← ソースコードは COPY しない（マウントで上書きされるため不要）
CMD ["npm", "run", "dev"]
```

### 実際の操作手順

```bash
# 1. 起動
docker compose up

# 2. ホスト側でコードを編集（エディタで App.js を変更するだけ）
#    → コンテナ内の /app/App.js も即座に変わる
#    → nodemon などがファイル変更を検知してアプリを再起動

# 3. 終了
docker compose down
```

### 注意点

バインドマウントには以下の制限があります：

| 問題                  | 説明                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| `node_modules` の衝突 | ホスト OS とコンテナ OS が異なると、ネイティブモジュールが動かないことがある                      |
| パフォーマンス        | macOS / Windows では大量の小さいファイルがある場合（`node_modules` など）I/O が遅くなることがある |
| 細かい制御が難しい    | 特定のファイルだけ同期する、などの細かい設定ができない                                            |

## 方法 2: `docker compose watch`（推奨・新しい方法）

Docker Compose v2.22 以降で利用できる機能です。ファイルの変更に応じて「同期する」「再ビルドする」「同期してサービスを再起動する」を**ファイルごとに細かく制御**できます。

### 3 つの `action`

| action         | 動作                                             | 使いどころ                                                                |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------- |
| `sync`         | ファイルをコンテナにコピーするだけ（再起動なし） | アプリ自体がホットリロードに対応しているとき（React, Vite など）          |
| `sync+restart` | ファイルをコピーしてサービスを再起動する         | アプリ本体は再ビルド不要だが再起動が必要なとき（設定ファイルの変更など）  |
| `rebuild`      | イメージを再ビルドしてコンテナを再作成する       | 依存関係ファイルが変わったとき（`package.json`, `requirements.txt` など） |

### compose.yaml の設定例（Node.js）

```yaml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    develop:
      watch:
        - action: sync          # ソースコードはビルドなしで即時同期
          path: ./src
          target: /app/src
          initial_sync: true
          ignore:
            - node_modules/     # node_modules は同期しない
        - action: rebuild       # package.json が変わったら再ビルド
          path: package.json
```

### compose.yaml の設定例（Python Flask）

```yaml
services:
  web:
    build: .
    ports:
      - "5000:5000"
    develop:
      watch:
        - action: sync          # .py ファイルはそのまま同期
          path: ./app
          target: /app
        - action: rebuild       # 依存関係が変わったら再ビルド
          path: requirements.txt
```

### compose.yaml の設定例（nginx 設定ファイルの変更）

```yaml
services:
  web:
    build: .
    develop:
      watch:
        - action: sync          # ソースコードは同期
          path: ./src
          target: /app/src
          ignore:
            - node_modules/
        - action: sync+restart  # nginx の設定が変わったらサービスを再起動
          path: ./nginx/nginx.conf
          target: /etc/nginx/conf.d/default.conf
```

### 実際の操作手順

```bash
# 1. watch モードで起動（ビルド＋起動＋ファイル監視 を一括で行う）
docker compose up --watch

# または、アプリのログと watch のログを分けたい場合：
docker compose up -d         # バックグラウンドで起動
docker compose watch         # watch を別途起動

# 2. ホスト側でコードを編集する
#    → action: sync の対象ファイル → コンテナ内に即座にコピーされる
#    → action: rebuild の対象ファイル → 自動でイメージを再ビルドして再起動

# 3. 終了
Ctrl+C
docker compose down
```

## バインドマウント vs Compose Watch

|                            | バインドマウント                       | Compose Watch                          |
| -------------------------- | -------------------------------------- | -------------------------------------- |
| **利用可能なバージョン**   | すべて                                 | Docker Compose v2.22 以降              |
| **細かい制御**             | できない（ディレクトリ全体をマウント） | できる（ファイルごとにアクション設定） |
| **`node_modules` の扱い**  | `ignore` 的な設定が難しい              | `ignore` で簡単に除外できる            |
| **クロスプラットフォーム** | ネイティブモジュールの問題が起きやすい | コンテナ内でビルドするため安全         |
| **パフォーマンス**         | macOS/Windows では遅くなることがある   | 変更ファイルだけを転送するため効率的   |
| **設定の複雑さ**           | シンプル                               | 少し設定が必要                         |

## 開発・本番 の構成を分ける方法

### マルチステージビルドで使い分ける

```dockerfile
# syntax=docker/dockerfile:1

FROM node:22-alpine AS base
WORKDIR /app
COPY package*.json ./
RUN npm install

# 開発用ステージ（ソースはマウント想定なので COPY しない）
FROM base AS dev
CMD ["npm", "run", "dev"]

# 本番用ステージ（ソースコードを焼き込む）
FROM base AS prod
COPY . .
RUN npm run build
CMD ["node", "dist/server.js"]
```

```yaml
# compose.yaml（開発用）
services:
  app:
    build:
      context: .
      target: dev      # ← dev ステージを使う
    volumes:
      - .:/app
      - /app/node_modules
    ports:
      - "3000:3000"
```

```yaml
# compose.prod.yaml（本番用）
services:
  app:
    build:
      context: .
      target: prod     # ← prod ステージを使う
    ports:
      - "3000:3000"
```

```bash
# 開発時
docker compose up

# 本番ビルド
docker compose -f compose.prod.yaml build
```

### ホットリロードに対応しているツール（言語別）

| 言語                 | ツール                | 起動コマンド例               |
| -------------------- | --------------------- | ---------------------------- |
| Node.js              | `nodemon`             | `nodemon server.js`          |
| Node.js (TypeScript) | `ts-node-dev`         | `ts-node-dev src/index.ts`   |
| Python (Flask)       | Flask の開発モード    | `flask run --debug`          |
| Python (Django)      | Django の開発サーバー | `python manage.py runserver` |
| Go                   | `air`                 | `air`                        |
| Ruby on Rails        | デフォルトで対応      | `rails server`               |
| Java (Spring Boot)   | Spring Boot DevTools  | `mvn spring-boot:run`        |

## まとめ

```
コード変更のたびに再ビルドが必要になる場面:
  → Dockerfile に COPY でコードを焼き込んでいる本番構成のとき

開発中に再ビルドせずに変更を反映する方法:
  1. バインドマウント: volumes に .:/app と書く（シンプルだが制御が荒い）
  2. Compose Watch: develop.watch で同期ルールを細かく設定する（推奨）
```

どちらの方法でも、コンテナ内のアプリが `nodemon` や `flask --debug` などのホットリロード対応コマンドで起動していれば、**ファイルを保存するだけでアプリが自動反映**されます。再ビルドは不要です。
