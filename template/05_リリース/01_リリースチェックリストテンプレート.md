# リリースチェックリスト

> **位置づけ：** 本番リリース当日に使用する作業確認票。全項目にチェックを入れた上で、リリース責任者がサインオフする。
> **使い方：** リリースごとにコピーして使う。実施した項目は担当者・実施時刻を必ず記録する。

## 5. ロールバック手順

> リリース後確認で問題が発生した場合、以下の判断基準と手順でロールバックする。

### ロールバック判断基準

| 状況                                           | 判断                       |
| ---------------------------------------------- | -------------------------- |
| 致命的バグが発生し、主要業務が遂行不能         | **即ロールバック**         |
| スモークテストがNGで原因特定に〇〇分以上かかる | **ロールバック推奨**       |
| 軽微なバグのみで回避策がある                   | **ホットフィックスで対応** |

### ロールバック手順

| #   | 作業内容                                           | 担当者 | 実施時刻 | 結果 |
| --- | -------------------------------------------------- | ------ | -------- | ---- |
| 1   | メンテナンス画面を有効化する                       |        |          |      |
| 2   | 直前バージョンのアプリケーションをデプロイする     |        |          |      |
| 3   | DBマイグレーションをロールバックする（必要な場合） |        |          |      |
| 4   | バックアップからのリストア（必要な場合）           |        |          |      |
| 5   | サービスを再起動する                               |        |          |      |
| 6   | メンテナンス画面を解除する                         |        |          |      |
| 7   | スモークテストを再実施する                         |        |          |      |
