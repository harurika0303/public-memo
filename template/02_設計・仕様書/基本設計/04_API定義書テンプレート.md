# API定義書

> **位置づけ：** 基本設計の一部。フロントエンドとバックエンドの実装の基準とする。OpenAPI（Swagger）を併用する場合は本書が設計方針・補足説明の役割を担う。
> **命名規則：** エンドポイントはリソース名を複数形スネークケースで記述する（例: `/api/users`, `/api/order_items`）。

## 1. 共通仕様

### 1.1 認証

| 項目                   | 内容                                               |
| ---------------------- | -------------------------------------------------- |
| 認証方式               | Bearer Token（JWT） / Cookie セッション            |
| トークン送信方法       | リクエストヘッダー `Authorization: Bearer <token>` |
| トークン有効期限       | 〇時間（アクセストークン）                         |
| 未認証時のレスポンス   | HTTP 401                                           |
| 権限不足時のレスポンス | HTTP 403                                           |

### 1.2 リクエスト共通仕様

| 項目             | 内容                                     |
| ---------------- | ---------------------------------------- |
| Content-Type     | `application/json`                       |
| 文字コード       | UTF-8                                    |
| 日付フォーマット | ISO 8601（`YYYY-MM-DDTHH:mm:ssZ`）       |
| ページネーション | クエリパラメーター `?page=1&per_page=20` |

### 1.3 レスポンス共通形式

**成功時（2xx）**

```json
{
  "data": { /* リソースオブジェクト or 配列 */ },
  "meta": {            // 一覧取得時のみ
    "current_page": 1,
    "per_page": 20,
    "total": 150
  }
}
```

**エラー時（4xx / 5xx）**

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "入力内容に誤りがあります",
    "details": [       // バリデーションエラー時のみ
      { "field": "email", "message": "メールアドレスの形式が正しくありません" }
    ]
  }
}
```

### 1.4 共通エラーコード一覧

| HTTPステータス | エラーコード          | 説明                         |
| -------------- | --------------------- | ---------------------------- |
| 400            | BAD_REQUEST           | リクエストの形式が不正       |
| 401            | UNAUTHORIZED          | 未認証または期限切れトークン |
| 403            | FORBIDDEN             | アクセス権限がない           |
| 404            | NOT_FOUND             | リソースが存在しない         |
| 409            | CONFLICT              | リソースの競合（重複登録等） |
| 422            | VALIDATION_ERROR      | バリデーションエラー         |
| 429            | TOO_MANY_REQUESTS     | レートリミット超過           |
| 500            | INTERNAL_SERVER_ERROR | サーバー内部エラー           |

## 3. API詳細

### API-001：ログイン

| 項目               | 内容          |
| ------------------ | ------------- |
| **API ID**         | API-001       |
| **メソッド**       | POST          |
| **エンドポイント** | `/auth/login` |
| **認証要否**       | 不要          |
| **レートリミット** | 〇回 / 分     |
| **対応FR#**        | FR-001        |

**リクエスト**

```
POST /api/auth/login
Content-Type: application/json
```

| パラメーター | 型     | 必須 | バリデーション | 説明               |
| ------------ | ------ | ---- | -------------- | ------------------ |
| email        | string | ○    | メール形式     | ログインID         |
| password     | string | ○    | 〇文字以上     | パスワード（平文） |

```json
{
  "email": "user@example.com",
  "password": "Password123!"
}
```

**レスポンス（成功: 200）**

```json
{
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_in": 3600,
    "user": {
      "id": 1,
      "name": "山田 太郎",
      "email": "user@example.com",
      "role": "user"
    }
  }
}
```

**エラーレスポンス**

| ステータス | エラーコード      | 条件                     |
| ---------- | ----------------- | ------------------------ |
| 401        | UNAUTHORIZED      | メール・パスワード不一致 |
| 422        | VALIDATION_ERROR  | 必須項目未入力・形式不正 |
| 429        | TOO_MANY_REQUESTS | 〇回以上の連続失敗       |

### API-004：〇〇一覧取得

| 項目               | 内容      |
| ------------------ | --------- |
| **API ID**         | API-004   |
| **メソッド**       | GET       |
| **エンドポイント** | `/〇〇`   |
| **認証要否**       | 要        |
| **対応FR#**        | FR-〇〇〇 |

**クエリパラメーター**

| パラメーター | 型      | 必須 | デフォルト   | 説明                               |
| ------------ | ------- | ---- | ------------ | ---------------------------------- |
| page         | integer |      | 1            | ページ番号                         |
| per_page     | integer |      | 20           | 1ページあたりの件数（最大100）     |
| keyword      | string  |      |              | キーワード絞り込み                 |
| status       | string  |      |              | ステータス絞り込み（例: `active`） |
| sort         | string  |      | `created_at` | ソートキー                         |
| order        | string  |      | `desc`       | ソート順（`asc` / `desc`）         |

**リクエスト例**

```
GET /api/〇〇?page=1&per_page=20&keyword=test&status=active
Authorization: Bearer <token>
```

**レスポンス（成功: 200）**

```json
{
  "data": [
    {
      "id": 1,
      "column_1": "値1",
      "column_2": "値2",
      "created_at": "2026-05-10T09:00:00+09:00"
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 150,
    "last_page": 8
  }
}
```

### API-007：〇〇更新

| 項目               | 内容                                                    |
| ------------------ | ------------------------------------------------------- |
| **API ID**         | API-007                                                 |
| **メソッド**       | PUT                                                     |
| **エンドポイント** | `/〇〇/:id`                                             |
| **認証要否**       | 要                                                      |
| **補足**           | 全フィールドを送信する（部分更新の場合は PATCH を使う） |

**リクエストボディ**（API-006と同じフィールド）

**レスポンス（成功: 200）**

更新後のリソースオブジェクトを返す（API-005と同じ形式）。

### API-008：〇〇削除

| 項目               | 内容                                     |
| ------------------ | ---------------------------------------- |
| **API ID**         | API-008                                  |
| **メソッド**       | DELETE                                   |
| **エンドポイント** | `/〇〇/:id`                              |
| **認証要否**       | 要                                       |
| **補足**           | 論理削除の場合は `deleted_at` を設定する |

**レスポンス（成功: 204）**

レスポンスボディなし。

**エラーレスポンス**

| ステータス | エラーコード | 条件                         |
| ---------- | ------------ | ---------------------------- |
| 404        | NOT_FOUND    | 指定IDのリソースが存在しない |
