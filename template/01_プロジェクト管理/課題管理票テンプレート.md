# 課題管理票（Issue Log）

> **目的：** バグ以外の「設計上の懸念・調整事項・保留・決定待ち」を継続的に管理する。バグはテスト/バグ報告票で管理し、本票はプロジェクト運営上の課題を対象とする。
> **更新ルール：** PMが週次定例で内容を最新化する。解決済みは削除せず「解決済」のままアーカイブする。

## 種別の定義

| 種別         | 定義                                             |
| ------------ | ------------------------------------------------ |
| **課題**     | 解決すべき具体的な問題がすでに発生している       |
| **懸念**     | まだ問題にはなっていないが、今後リスクになりうる |
| **決定待ち** | 要件・設計・方針について意思決定が必要な事項     |
| **情報共有** | 決定・対応は不要だが関係者に周知すべき事項       |

## 優先度の定義

| 優先度 | 定義                                                       |
| ------ | ---------------------------------------------------------- |
| **高** | プロジェクトの進行が止まる、またはマイルストーンに影響する |
| **中** | 対応しないと後工程に影響するが、即座には止まらない         |
| **低** | 影響は軽微。対応は余裕があるときでよい                     |

## ステータスの定義

| ステータス   | 定義                                           |
| ------------ | ---------------------------------------------- |
| **対応中**   | 担当者が調査・対応を進めている                 |
| **確認待ち** | ステークホルダーや外部への確認・回答待ちの状態 |
| **保留**     | 一時的に対応を止めている（理由を詳細欄に記載） |
| **解決済**   | 対応が完了し、クローズされた                   |
| **対応不要** | 検討の結果、対応しないことが決定された         |
