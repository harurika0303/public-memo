## 2. 定常業務（日次）

### 2.1 朝の状態確認

**実施タイミング：** 毎営業日 〇〇時

| #   | 確認項目                   | 確認方法                                                      | 正常の基準                              | 異常時の対応                             |
| --- | -------------------------- | ------------------------------------------------------------- | --------------------------------------- | ---------------------------------------- |
| 1   | サービスの疎通確認         | `curl -I https://〇〇.〇〇.co.jp` またはブラウザでアクセス    | HTTP 200 が返ること                     | 障害対応フローを参照                     |
| 2   | エラーログの確認           | 監視ダッシュボードまたは `tail -n 100 /var/log/app/error.log` | ERRORが0件、または想定内の件数          | 内容を確認し、必要に応じて開発担当へ報告 |
| 3   | 前夜のバッチ処理の完了確認 | バッチ実行ログを確認                                          | 全バッチが正常終了（exit 0）            | 担当者に報告し再実行を検討               |
| 4   | サーバーリソース確認       | ダッシュボードでCPU・メモリ・ディスクを確認                   | CPU < 80%、メモリ < 80%、ディスク < 70% | 異常値の場合は担当者へ報告               |

## 3. 定常業務（週次）

### 3.1 バックアップ確認

**実施タイミング：** 毎週〇曜日 〇〇時

| #   | 確認項目                                                           | 確認方法                                     | 記録                       |
| --- | ------------------------------------------------------------------ | -------------------------------------------- | -------------------------- |
| 1   | DBバックアップが作成されていること                                 | バックアップストレージを確認                 | 最新ファイル名と日時を記録 |
| 2   | バックアップのファイルサイズが妥当なこと                           | ファイルサイズが先週比で極端に小さくないこと |                            |
| 3   | バックアップの保持期間ルール通りに古いファイルが削除されていること | 〇日以上前のファイルが残っていないこと       |                            |

### 3.2 セキュリティアップデート確認

**実施タイミング：** 毎週〇曜日

```bash
# Linuxの場合（更新可能なパッケージ確認）
apt list --upgradable 2>/dev/null | grep -i security

# Dockerイメージの更新確認
docker pull <image-name> --dry-run
```

> セキュリティアップデートが存在する場合は、テスト環境で適用確認後に本番へ適用する。

## 6. デプロイ手順

> 本番デプロイはリリースチェックリストと合わせて実施すること。

```bash
# 1. サーバーへ接続
ssh -i ~/.ssh/〇〇.pem user@〇〇.〇〇.co.jp

# 2. アプリケーションディレクトリに移動
cd /var/www/〇〇

# 3. メンテナンスモードを有効化
php artisan down

# 4. 最新コードを取得
git pull origin main

# 5. 依存パッケージを更新
composer install --no-dev --optimize-autoloader

# 6. DBマイグレーション実行
php artisan migrate --force

# 7. キャッシュをクリア・再生成
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 8. メンテナンスモードを解除
php artisan up

# 9. 動作確認（スモークテスト）
curl -I https://〇〇.〇〇.co.jp
```

## 7. バックアップとリストア手順

### 7.1 DBバックアップ（手動）

```bash
# PostgreSQLの場合
pg_dump -U 〇〇 -Fc 〇〇_production > /backup/db_$(date +%Y%m%d_%H%M%S).dump

# MySQLの場合
mysqldump -u 〇〇 -p 〇〇_production | gzip > /backup/db_$(date +%Y%m%d_%H%M%S).sql.gz
```

### 7.2 DBリストア

```bash
# PostgreSQLの場合
pg_restore -U 〇〇 -d 〇〇_production /backup/db_YYYYMMDD_HHMMSS.dump

# MySQLの場合
gunzip < /backup/db_YYYYMMDD_HHMMSS.sql.gz | mysql -u 〇〇 -p 〇〇_production
```

> ⚠️ リストアを実行すると、リストア後の変更データは失われます。必ず担当者（PM・システム責任者）の承認を得てから実行してください。
