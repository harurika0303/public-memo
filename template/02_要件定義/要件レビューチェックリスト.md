# 要件レビューチェックリスト

> **位置づけ：** 要件検証（Validation）フェーズで使用する。要件定義書・SRSの品質を確認するチェックリスト。
> **参照規格：** ISO/IEC/IEEE 29148:2018（要件の品質特性：完全性・一貫性・曖昧さなし・検証可能性・実現可能性・追跡可能性）
> **使い方：** 要件定義書・SRS それぞれに対してレビュー実施前に配布し、各レビュアーが記入する。

---

## ドキュメント情報

| 項目                 | 内容                         |
| -------------------- | ---------------------------- |
| **プロジェクト名**   |                              |
| **レビュー対象文書** | 要件定義書 v〇〇 / SRS v〇〇 |
| **レビュー実施日**   | YYYY-MM-DD                   |
| **レビュアー**       |                              |
| **記録者**           |                              |

---

## 判定記号

| 記号 | 意味                                   |
| ---- | -------------------------------------- |
| ✅    | 問題なし（OK）                         |
| ❌    | 問題あり（要修正）                     |
| △    | 軽微な指摘あり（要確認）               |
| N/A  | 対象外（本プロジェクトには該当しない） |

## 4. 機能要件

### 4.1 完全性（Complete）

| #   | チェック項目                                               | 判定 | 指摘内容・コメント |
| --- | ---------------------------------------------------------- | ---- | ------------------ |
| 1   | 全ユースケースに対応する機能要件が存在するか               |      |                    |
| 2   | 正常系だけでなく、代替フロー・例外フローも定義されているか |      |                    |
| 3   | 入力・処理・出力がすべての機能で定義されているか           |      |                    |
| 4   | 画面・帳票・CSVなどの出力形式が明確か                      |      |                    |
| 5   | 外部システム連携の全接点が定義されているか                 |      |                    |

### 4.2 曖昧さなし（Unambiguous）

<!-- 「できるだけ速く」「なるべく多く」「適切な」などの曖昧な表現を排除する。 -->

| #   | チェック項目                                                                 | 判定 | 指摘内容・コメント |
| --- | ---------------------------------------------------------------------------- | ---- | ------------------ |
| 1   | 「できるだけ」「速やかに」「適切な」等の定量化できない表現が使われていないか |      |                    |
| 2   | 「等」「など」で具体的な対象が曖昧になっていないか                           |      |                    |
| 3   | 複数の解釈が可能な記述がないか                                               |      |                    |
| 4   | 条件分岐（if/else）が明確に定義されているか                                  |      |                    |

### 4.3 検証可能性（Verifiable）

| #   | チェック項目                                     | 判定 | 指摘内容・コメント |
| --- | ------------------------------------------------ | ---- | ------------------ |
| 1   | 各要件に対して「テストでOK/NGを判定できる」か    |      |                    |
| 2   | 受入基準（合格基準）が定量的に記載されているか   |      |                    |
| 3   | 業務ルールが具体的な条件と結果で記述されているか |      |                    |

### 4.4 優先度

| #   | チェック項目                                                 | 判定 | 指摘内容・コメント |
| --- | ------------------------------------------------------------ | ---- | ------------------ |
| 1   | 全ての機能要件に優先度（必須/推奨/任意等）が付与されているか |      |                    |
| 2   | 優先度の根拠（ビジネス価値・リスク・コスト等）が説明できるか |      |                    |

## 5. 非機能要件

| #   | チェック項目                                                              | 判定 | 指摘内容・コメント |
| --- | ------------------------------------------------------------------------- | ---- | ------------------ |
| 1   | **可用性：** 稼働率・RTO・RPOが数値で定義されているか                     |      |                    |
| 2   | **性能：** 応答時間・同時接続数・データ量が数値で定義されているか         |      |                    |
| 3   | **セキュリティ：** 認証方式・権限制御・暗号化・ログ要件が明記されているか |      |                    |
| 4   | **セキュリティ：** 個人情報・機密データの取り扱い方針が記載されているか   |      |                    |
| 5   | **運用・保守：** バックアップ方式・監視要件・保持期間が定義されているか   |      |                    |
| 6   | **移行：** 移行対象データ・移行方式・切り戻し方針が記載されているか       |      |                    |
| 7   | **環境・制約：** 対応ブラウザ・OS・法規制対応が明記されているか           |      |                    |

---

## 6. 一貫性（Consistent）

| #   | チェック項目                                                                                  | 判定 | 指摘内容・コメント |
| --- | --------------------------------------------------------------------------------------------- | ---- | ------------------ |
| 1   | 要件定義書とSRSの間で矛盾する記述がないか                                                     |      |                    |
| 2   | 要件と非機能要件の間で実現不可能な組み合わせがないか（例：「3秒以内」なのに「同時10万接続」） |      |                    |
| 3   | ユースケースと機能要件の間に矛盾・抜け漏れがないか                                            |      |                    |
| 4   | 制約条件が他の要件と矛盾していないか                                                          |      |                    |
