# 非機能要件定義書

> **目的：** システムの「何ができるか」（機能要件）ではなく、「どのように動くか」（品質・制約）を定義する。性能・可用性・セキュリティ・保守性など、後工程の設計・テストの基準となる。
> **作成タイミング：** 要件定義フェーズで機能要件と並行して作成する。

## 4. 保守性・運用要件

| 項目               | 要件                                                                    |
| ------------------ | ----------------------------------------------------------------------- |
| **ログ**           | アプリケーションエラーログ・アクセスログを出力し、〇〇日分保持する      |
| **監視**           | CPU・メモリ・ディスク・エラー率を監視し、閾値超過時にアラートを通知する |
| **デプロイ**       | 無停止デプロイ（ローリングアップデート等）ができること                  |
| **設定変更**       | 環境変数で設定値を変更でき、コード変更なしに切り替えられること          |
| **バッチ再実行**   | 障害時にバッチを特定日付指定で安全に再実行できること                    |
| **依存ライブラリ** | パッケージマネージャーでバージョン管理し、依存関係を明示する            |
